# Internationalization (binding)

NeNe Serve is a **six-locale application** (ADR 0011). This document is the operator and implementer guide.

**Authority: `ja`** (ADR 0011 Amendment 2026-07-15; Frontend Standard 04, I18N-8).
Message keys are authored in Japanese first and every other catalog — `en`
included — mirrors that key set. `en` remains the default locale and the runtime
fallback: authority (who owns the key set) and fallback (who answers at runtime)
are separate concerns.

## Locales

| File | Code |
| --- | --- |
| `locales/en.json` | `en` (default locale, runtime fallback) |
| `locales/ja.json` | `ja` (**authority — canonical key set**) |
| `locales/zh-Hans.json` | `zh-Hans` |
| `locales/ko.json` | `ko` |
| `locales/de.json` | `de` |
| `locales/es.json` | `es` |

## Key naming

- Dot-separated: `admin.placements.title`, `embed.loading`, `consent.measurement_label`
- Stable keys; never embed English prose as key names

## Rules

1. **Add keys to the authority catalog (`ja`) first** — every other locale, `en` included, follows in the same PR.
2. No user-visible literals in PHP/TypeScript except test fixtures.
3. Pluralization: use `key_one` / `key_other` suffix pattern (ICU optional Phase 2).
4. RTL locales: not in the six-locale set; add via future ADR.

## Embed selection

`serve.js` reads `data-locale` → fallback chain in ADR 0011.

## Admin UI

- Language switcher persists per user in `user_preferences.locale`
- Organization default in `organization_settings.default_locale`

## CI

```bash
composer locales:check   # key parity across six files
```

Active in `.github/workflows/ci.yml`: every push/PR runs `locales:check`, which
flattens nested keys to dotted paths, fails on any missing/extra key vs the
authority `ja.json`, and verifies `_one`/`_other` pluralization pairs. Catalogs
are nested JSON; `_meta` is ignored. Add new keys to `ja.json` and all five other
locales in the same PR (ADR 0011).

The admin SPA catalogs (`frontend/src/shared/i18n/messages/*.ts`) follow the same
authority and are checked by `tsc`: `MessageKey` derives from `ja`
(`keyof typeof ja`), and every other catalog is typed
`MessageCatalog` (= `Record<MessageKey, string>`), so a missing or extra key is a
compile error.

## Repository docs

ADR and scope docs stay **English** (ADR 0008). Only `locales/` holds translations.
