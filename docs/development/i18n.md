# Internationalization (binding)

NeNe Serve is a **six-locale application** (ADR 0011). This document is the operator and implementer guide.

## Locales

| File | Code |
| --- | --- |
| `locales/en.json` | `en` (default, canonical key set) |
| `locales/ja.json` | `ja` |
| `locales/zh-Hans.json` | `zh-Hans` |
| `locales/ko.json` | `ko` |
| `locales/de.json` | `de` |
| `locales/es.json` | `es` |

## Key naming

- Dot-separated: `admin.placements.title`, `embed.loading`, `consent.measurement_label`
- Stable keys; never embed English prose as key names

## Rules

1. **English keys in `en.json` first** — other locales follow in the same PR.
2. No user-visible literals in PHP/TypeScript except test fixtures.
3. Pluralization: use `key_one` / `key_other` suffix pattern (ICU optional Phase 2).
4. RTL locales: not in the six-locale set; add via future ADR.

## Embed selection

`serve.js` reads `data-locale` → fallback chain in ADR 0011.

## Admin UI

- Language switcher persists per user in `user_preferences.locale`
- Organization default in `organization_settings.default_locale`

## CI (planned)

```bash
composer locales:check   # key parity across six files
```

## Repository docs

ADR and scope docs stay **English** (ADR 0008). Only `locales/` holds translations.
